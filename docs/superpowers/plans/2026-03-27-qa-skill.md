# QA Skill Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the GitHub Actions weekly-QA cron with a `/qa` Claude Code skill that dispatches parallel Playwright agents, has a lead agent triage results and decide re-runs, produces a merged bug report, then implements fixes on a new branch and opens a PR.

**Architecture:** A lead agent (the invoking Claude session) reads git history + the last bug report to build a priority matrix, dispatches up to 10 parallel subagents that each run one Playwright spec, collects their structured result blocks, optionally triggers a re-run round for flaky/high-priority failures, then runs `merge-reports.js` to produce `docs/qa/bug-report-{date}.md`. After committing the report the lead creates a fix branch, implements fixes ordered by severity, verifies with `npm run build`, and opens a PR via `gh`.

**Tech Stack:** Playwright Test CLI, Node ESM, Claude Code Agent tool, `gh` CLI, Supabase (via existing QA helpers)

## Task 2: Add idempotency guard to qa/global-setup.js

**Files:**
- Modify: `qa/global-setup.js`

When 6 parallel agents each run `npx playwright test [spec] --config qa/playwright.config.js`, each invocation calls `globalSetup`. Without this guard, Supabase seeding runs concurrently 6×, risking duplicate households and race conditions.

**Guard logic:** at the start of `globalSetup()`, check if `qa-session.json` in `os.tmpdir()` already exists and is < 10 minutes old. If so, skip all seeding and return immediately.

- [ ] **Step 1: Read `qa/global-setup.js` to find the exact insertion point**

  The insertion point is the very first line of the `export default async function globalSetup()` body, before the Supabase ping.

- [ ] **Step 2: Add the guard at the top of `globalSetup()`**

  The function currently starts:
  ```js
  export default async function globalSetup() {
    // Verify Supabase connectivity before doing anything
    console.log('[setup] Verifying Supabase connection...');
  ```

  Change it to:
  ```js
  export default async function globalSetup() {
    // ── Idempotency: skip re-seed if session file is < 10 minutes old ──────
    const sessionPath = path.join(os.tmpdir(), 'qa-session.json');
    if (fs.existsSync(sessionPath)) {
      const ageMs = Date.now() - fs.statSync(sessionPath).mtimeMs;
      if (ageMs < 10 * 60 * 1000) {
        console.log('[setup] Session file is fresh (<10 min) — skipping re-seed.');
        return;
      }
    }

    // Verify Supabase connectivity before doing anything
    console.log('[setup] Verifying Supabase connection...');
  ```

  Note: `path`, `os`, and `fs` are already imported at the top of the file — no new imports needed.

- [ ] **Step 3: Verify the rest of the function is unchanged after the guard**

  Read the file and confirm:
  - The Supabase ping is still there
  - `seedTestUser`, `createHousehold`, etc. are all still present
  - `writeSignal('setup', { setup_complete: true })` is still the last line

- [ ] **Step 4: Commit**

  ```bash
  git add qa/global-setup.js
  git commit -m "fix: make QA global-setup idempotent for parallel agent runs"
  ```

  ## Phase 6: Fix Phase

  ### 6a — Create fix branch

  ```bash
  BRANCH="qa-fixes-$(date +%Y-%m-%dT%H-%M)"
  git checkout -b "$BRANCH"
  echo "Branch: $BRANCH"
  ```

  ### 6b — Classify bugs from the report

  Read `docs/qa/bug-report-$(date +%Y-%m-%d).md`.

  For each bug (process in order: CRITICAL → HIGH → MEDIUM → LOW):

  **Implement a fix if the bug is:**
  - A CSS or styling issue (wrong color, missing class, layout problem)
  - Missing form validation (field accepts invalid values)
  - A logic or calculation error in `src/`
  - A missing UI element that the spec expects (button, badge, label)
  - A broken locator or selector that points to a renamed element

  **Mark BLOCKED and skip if the bug:**
  - Requires a new Supabase column, table, or migration
  - Describes ambiguous expected behavior (cannot determine correct output from the bug description alone)
  - Would require editing any file in `qa/`, `supabase/migrations/`, or `.github/`

  For BLOCKED bugs, add this comment in the closest relevant source file under `src/`:
  ```js
  // TODO QA-FIX-BLOCKED: BUG-XXX — <reason why it cannot be fixed automatically>
  ```

  ### 6c — Implement each fix

  For each fixable bug:
  1. Read the relevant file(s) in `src/`
  2. Implement the minimal change — no refactoring, no extra features, no unrelated edits
  3. Only write to: `src/`, `public/`, `vite.config.*`, `tailwind.config.*`

  **NEVER touch:** `qa/`, `supabase/migrations/`, `.github/`

  ### 6d — Build verification

  ```bash
  npm run build
  ```

  If the build fails:
  1. Read the full compiler/lint error output
  2. Identify the broken file and error type (TypeScript type error, missing import, etc.)
  3. Fix it — attempt 1
  4. Run `npm run build` again
  5. If still failing — attempt 2: re-read and fix
  6. If still failing after attempt 2: revert the responsible fix:
     ```bash
     git checkout -- path/to/broken/file.tsx
     ```
     Add a `// TODO QA-FIX-BLOCKED: BUG-XXX — build error, requires manual fix` comment.
     Run `npm run build` to confirm it now passes.

  ### 6e — Commit and push

  ```bash
  git add -A
  git diff --cached --quiet || git commit -m "fix: implement QA-detected fixes $(date +%Y-%m-%d)"

  COMMITS=$(git log origin/main..HEAD --oneline | wc -l)
  if [ "$COMMITS" -gt 0 ]; then
    git push origin "$BRANCH"
  else
    echo "No commits to push — no fixable bugs found."
  fi
  ```

  ### 6f — Open PR

  Only run this if the branch was pushed (commits > 0):

  ```bash
  TODAY=$(date +%Y-%m-%d)
  gh pr create \
    --title "fix: QA-detected bugs $TODAY" \
    --body "$(cat <<'PRBODY'
  ## Automated QA Fix PR

  Generated by the `/qa` skill.

  **Bug report:** See file path printed in Phase 5.

  **Review checklist:**
  - [ ] Review each fix against the original bug report
  - [ ] Run `npm run dev` and manually verify the fixed behaviors
  - [ ] Run `npm run build` to confirm no errors
  - [ ] Merge when satisfied

  Bugs marked `TODO QA-FIX-BLOCKED` in source files require manual attention.
  PRBODY
  )" \
    --base main \
    --head "$BRANCH"
  ```
  ```
